PL1005: Transitive axioms must fit the selected profile🔗

Development documentation generated from commit 0061ed6d2c66 with Lean 4.34.0; linter version unreleased (no released package). Moving route: /lean-plumb/dev/rules/PL1005/. Snapshot route for this commit: /lean-plumb/rev/0061ed6d2c66…/rules/PL1005/. Once this commit is published, its snapshot is kept by every later deployment. See versions and evidence.

Problem. A declaration's exact transitive axiom set is admissible, but its least foundation label is stronger than the claim of the surface it belongs to.

Action. Prove the same statement with fewer axioms, or deliberately raise the surface's claim in foundation_manifest.json and update its rationale.

What triggers it🔗

Each declaration receives the least label containing its exact axiom set. If that label exceeds the surface maximum, the declaration is rejected with applicability label-exceeds-claim.

The three logical labels are Kernel-only (no axioms), Choice-Free (a subset of propext and Quot.sound) and Standard-Logical (additionally Classical.choice). A surface's claim in foundation_manifest.json is the upper bound; each declaration is labeled from its own exact axiom set.

Why it matters🔗

A profile claim tells readers which logical principles every result on the surface may use. One declaration above the bound makes the claim false for the whole surface.

How to fix it🔗

  1. Find the axiom that raises the label in the diagnostic's axiom list, then find the lemma or tactic that introduces it (for example simp lemmas using propext, or classical reasoning using Classical.choice).

  2. Prove the statement constructively or with a narrower lemma so the exact set fits the claim.

  3. If the stronger foundation is intended, change the surface's claim and rationale explicitly; this changes the published claim and needs review.

Change to Fixture.lean:

The correction proves the same universally quantified reflexivity with an empty axiom set, under the unchanged Kernel-only claim, instead of routing through propext.

Required proof shape🔗

The replacement proves the same proposition. Classical, erased proofs are permitted when the surface claims Standard-Logical; executable behavior is a separate account (PL1007, PL3001, PL3002).

What a passing result establishes🔗

Every declaration's exact axiom set is within the selected surface maximum.

It does not establish:

  • Which label a declaration should have: the claim is a project decision, reviewed with its rationale.

Review obligations the rule-coverage map associates with this rule (identifiers of the checker's Residual account):

  • R-QUALIFY: the checker's detection is qualified for this invocation, toolchain and capability

Every accepted result lists all residual obligations as open, whatever rules it checked: R-INTENT, R-INVARIANT, R-LAWS, R-BOUNDARY, R-NONVACUITY, R-DOC, R-COST, R-QUALIFY (and R-GRAPH for a serialized-graph claim). A listed identifier is an open obligation, never a completed review.

Every accepted result also relies on these trusted mechanisms (the checker's Trusted account), which no rule verifies:

  • toolchain: Lean elaborator, kernel and compiler at the snapshot's toolchain identity

  • acquisition: manifest parsing, Lake loading, and source, configuration and dependency acquisition

  • extraction: environment extraction, compiler and worker processes, and JSON transport

  • runtime: native runtime and every execution boundary reported as trusted

Configuration and exceptions🔗

No source option, attribute or command-line flag makes this rule pass on a claimed surface. set_option linter.plumb false and plumb.localFoundation never waive it: lake lint, the build-lint policy target and axiomGate still apply the rule. Where Plumb's local linter reports a finding during a project build (axiomGate and the policy target keep it on by default; lake lint builds with it off, whatever the source sets linter.plumb to), that finding is a build warning, so the result is INCOMPLETE under PL2003 instead of carrying this rule's finding. Switching the local linter off changes which finding is reported, never whether the result is accepted. Hiding the diagnostic does not establish the property it checks.

The surface maximum is the claim of its entry in foundation_manifest.json; axiomGate --file F --claim PROFILE audits one file under an explicit profile. In the editor, plumb.localFoundation selects local feedback only.

Project enforcement runs through lake lint (incremental), lake lint -- --fresh and lake exe axiomGate (fresh whole-project audits from empty build output), and the build-lint policy target. See the adoption guide.

Limitations and unsupported cases🔗

The label is computed from the exact transitive set; a proof that merely could avoid an axiom still carries it until rewritten.
